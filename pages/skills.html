Skills

Repeatable CDE processes packaged as Claude skills. Each one captures how we do a recurring task so anyone gets the same quality output, the same way, every time.

What is a skill? A skill is a saved process Claude already knows. You either type /skill-name or just describe the task in plain language and Claude loads the right process automatically. You do not need to remember the steps. The skill does.
Where they live: Skills are installed at ~/.claude/skills/ on each person's machine. If a skill below does not show up when you type /, you need to install it (ask Balaji or copy the skill folder from the shared setup).

How to use a skill

Two ways. Both work.

Option A: Just describe the task

I have a Google Ads search terms export for [client]. Can you give me a performance recap and a negative keyword scrub?

Claude recognizes the task and loads the matching skill on its own.

Option B: Call it directly

/google-ads-update

Type a slash and the skill name. Useful when you want to be explicit.

competitive-audit

Competitor teardown: landing pages plus the ads they are actually running, compiled into a branded deck.

When to use it

Use it for
A client asks "what are our competitors doing?", landing-page benchmarking, or auditing competitor ad creative.
What it produces
A branded PPTX: competitor hero screenshots, ad-library creative, positioning patterns, and recommendations tied to the client's own data.

What it does

Captures competitor landing pages (Playwright screenshots), pulls their running ads from Meta Ad Library, Google Ads Transparency Center, TikTok, and LinkedIn, analyzes positioning patterns, and builds the deck. Every observation ties back to the client's own search or ad data.

Example prompt

Run a competitive audit for [client]. Competitors are [A], [B], [C]. Capture their landing pages and the ads they are running, then build a deck. Here is the client's search terms data: [attach/paste]

google-ads-update

Turns a Google Ads search-terms export into a performance recap, a negative keyword scrub, and a client-ready email.

When to use it

Use it for
Weekly or monthly client updates, negative keyword scrubs, drafting a performance email. Works for any paid-search client.
What it produces
Performance numbers, search terms sorted into four buckets (winning, fixable misses, negate, competitor brands), a paste-ready negatives list, and an email draft.

The key judgment it makes

It separates real missed opportunities (buyer-intent queries that did not convert) from match-type noise (broad research queries that should be negated, not "fixed"). A high-impression zero-click term is often a leak, not unmet demand.

Example prompt

Here is the Google Ads search terms report for [client]: [attach CSV] Give me a performance recap, a negative keyword scrub (check against our existing negatives), and a draft update email for the client.

cde-proposal

Builds a client proposal as a GitHub Pages site that matches the CDE design system exactly.

When to use it

Use it for
Building or updating a client proposal, pricing page, or scope of work.
What it produces
A single-page proposal site with the CDE sidebar, animated hero, pricing blocks, and a passed Playwright QA, ready to deploy to GitHub Pages.

What it does

Reads the full Proposal Template Protocol first, then builds to spec. It handles the design system, section order, hero readability QA, and deployment so you do not have to remember any of it.

Example prompt

Build a proposal for [client]. Services we are proposing: [list]. Budget range: [if known]. Follow the CDE proposal protocol and QA it with Playwright before we share.

cde-pitch-deck

Preps a new-business pitch: structured research, then a plain-English problem and solution story.

When to use it

Use it for
Prepping a pitch for a new prospect, or running pre-pitch research before building a deck.
What it produces
A filled-in research brief (website, competitors, Google search, Keyword Planner, Meta Ad Library) plus a structured problem and solution story to hand to a designer.

The golden rule it follows

Write everything like you are explaining it to someone at a bar. Zero jargon. If a normal person would not nod along, it gets rewritten.

Example prompt

Prep a pitch for [prospect] at [website]. Run the research: their site, their top competitor, Google search, and Meta Ad Library. Then give me the problem and solution story for the deck.

Rules every skill follows

These are baked in so you do not have to police them.

No em dashes
All client-facing copy uses periods, commas, or parentheses instead.
No personal names
Client deliverables use "Core Digital Expansion", never an individual's name.
Right currency, right brand
UAE clients priced in AED. Drip and ConciergeMD work uses 12100 Collective branding, not CDE.
QA before sharing
Web deliverables are checked with Playwright. Research uses official primary sources only.
